## Cache-lock failure and regression proof

The instrumented Node 26 benchmark captured this sanitized failure:

```text
processing-cache-lock-unavailable
Cause: locked; lock present: true; mutex present: false; pid alive: false; same host: false.
```

The retained record and read-only inspection established a hostname mismatch, not PID reuse or
an interrupted reclaim mutex. Release checked the current hostname in addition to its captured
nonce and PID. The deterministic `releases its own lock after the local hostname changes` test
in `src/build/private-lock.test.js` failed before the repair: the owner called release but its
lock remained. The same test passes after release uses the captured nonce and PID. Replacement
locks remain protected, and a foreign-host lock is never reclaimed merely because its PID is
absent locally. No process-start lookup or filesystem retry was added without evidence.

Inspection is read-only and non-throwing, record reads use `O_NOFOLLOW`, reclaim-mutex
filesystem errors retain their codes, and acquisition/release diagnostics expose only the
bounded cause and boolean facts. Invalid/symlink records, retained mutexes, filesystem failures,
redaction, replacement protection and eight simultaneous contenders have regression coverage.
