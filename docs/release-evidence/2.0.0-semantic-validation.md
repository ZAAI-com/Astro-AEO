## Semantic evidence carry-forward

The full gate rebuilt `fixtures/golden-1.2` and `fixtures/schema-tools/static`. Their rendered
`dist/index.html` files have the exact SHA-256 values recorded for the inputs submitted to external
validators in [1.5.3's evidence](1.5.3-semantic-validation.md) and carried forward through
[1.6.1's](1.6.1-semantic-validation.md). No component or schema builder source changed. No new
external validator submission was performed or is claimed; the recorded results carry forward for
those byte-identical inputs, with the same disclosed merchant-listing limitations.

## Compatibility evidence

- `fixtures/golden-1.0`: built from its configuration translated into canonical keys, every
  artifact still matches the frozen 1.0 bytes on Astro 7.3.5.
- `fixtures/config-compat`: the 1.0-spelled config stops the build and names all 24 removed paths
  it uses; the canonical build is byte-identical to `expected-1.6.json`, generated once from the
  published 1.6.1 source.
- `scripts/compatibility-report.mjs` against `1.6.1`: 53 removals (11 declarations, 42 schema
  paths), all in the allowlist; the only addition is the `aeo-head-author-removed` audit rule;
  the only value changes are the `astro` peer and `node` engine floors.
