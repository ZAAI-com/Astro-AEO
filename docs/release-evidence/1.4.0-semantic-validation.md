## Semantic source changed in 1.4.0

`git diff --name-only origin/main...HEAD` lists three paths under the JSON-LD surface.

| Path | Change | Reachable from the submitted fixture |
| --- | --- | --- |
| `src/schema.js` | Adds `createTechArticle()`, one more `buildEntity` wrapper. Renames a JSDoc-local typedef. No existing builder, merge, validation or serialization code changes. | No. The fixture uses no TechArticle. |
| `src/core/head.js` | The inferred site-wide `WebSite` entity omits `inLanguage` when the site declares more than one Astro i18n locale. Repeated `generator` meta tags are exempt from the duplicate-metadata diagnostic. | No. The fixture has one locale, so its `WebSite` bytes are unchanged; the second change affects a diagnostic, not output. |
| `components/index.d.ts` | Adds the optional `version` prop to the `AeoPage` declaration. | No. A type declaration, and `AeoPage` emits no JSON-LD. |

The byte-identical fixture hash above proves the first three rows for the submitted page. The
`TechArticle` entity, the one new public output, was submitted separately (results below). The
multilingual `WebSite` entity without `inLanguage` was not submitted: the change removes one optional
property from an entity type both validators already accepted, and it is pinned by `src/core/head.test.js`
and the `recipes/i18n` build.
