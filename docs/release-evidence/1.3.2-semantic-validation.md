## Behavior change recorded for this patch

Projects that redirect their own `/404` now receive development-only fallback routes so Astro-AEO
artifact requests reach middleware instead of the redirect. This affects development routing and
diagnostics only. Build output, production adapter behavior, configuration, and JSON-LD output are
unchanged.

A rewrite the development loopback rescued is no longer reported as a rewrite failure, for a
companion and for a corpus page alike. A loopback that never loaded at all still names its cause in
the terminal, so a companion of a prerendered page cannot 404 silently.

One combination stays uncovered on Astro 6 and older: a project that redirects its own `/404` and
also sets `trailingSlash: 'always'`. Those versions derive a dynamic route's trailing-slash pattern
from the project configuration alone, so the injected `.md` catch-all matches `/about.md/` and not
`/about.md`. The exact artifact paths are fixed on every supported Astro, and Astro 7 exempts
dynamic endpoint patterns carrying a file extension. The limitation is documented in `README.md` and
in the 1.3.2 changelog entry, and a test asserts the per-major behavior instead of hiding it.

## Known defect carried by this release

On a development server that redirects its own `/404`, a project route sitting at an exact artifact
path is shadowed by the injected prerendered fallback route and answers an empty 404 instead of
winning. Enabling `corpus.small` in the ownership fixture made that assertion real and it failed, so
`src/runtime/fallback-routes.dev.test.js` marks the case `test.fails` with the reasoning rather than
weakening it. Astro exposes no `removeRoute` and resolves no routes while `injectRoute` is still
available, so the correction belongs at dispatch and is not attempted here.

Scope: `astro dev` only, only for projects whose `/404` is a redirect, and only for a project route
placed at a path a core generator already claims. Build output, adapter builds, production routing,
and JSON-LD output are unaffected. The release owner accepted this for 1.3.2 and it is tracked for
1.3.3.
