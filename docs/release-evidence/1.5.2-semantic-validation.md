# Astro-AEO 1.5.2 semantic validation evidence

Semantic validation for 1.5.2 carries forward from the 1.5.1 record. 1.5.2 reads multi-line
Starlight component tags, spaces unwrapped wrappers in tables kept as HTML, omits an unusable
`FaqJsonLd` `id`, and types `page.locale` for section predicates. It then fixes ten defects found by
a read-only audit of 1.4.0 (F1 to F10 below), none of which touches a JSON-LD-producing module:
the audit's reference check (F6) changes only `src/audit/`. The `FaqJsonLd` change touches a
JSON-LD-producing component, so the carry-forward is proven by rebuilding the fixture rather than
asserted from the diff: the rebuilt fixture HTML is byte-identical to the 1.4.0, 1.5.0 and 1.5.1
submission, and no resubmission to the external validators was required. The external services
are manual release checks, not automated release dependencies.

## Behavior change recorded for this release

A Starlight component tag spread over several lines converts like a one-line tag, or falls back to
rendered extraction when it is unknown, computed or never ends. Adjacent styling-only `<div>` and
`<span>` wrappers in a table kept as HTML are separated by one space. `FaqJsonLd` omits an unusable
`id`. Section predicates are typed with `SectionPage`, which adds `locale` to `AeoPage`.

The audit fixes change output only where the old output was wrong: titles after a RegExp
`stripTitleSuffix` change, stale files kept (and reported) by a build whose cache is read-only, `.md`
companions of `.mdx` content entries without raw MDX, request-time corpus manifests listing
companions, no false `robots-unknown-line` for `Content-Signal` or `schema.unresolved-reference` for
sibling entities, JUnit cases that follow `--fail-on`, and an Apache snippet scoped to `.md`. The
changelog lists each change.
