# 2.0.0 decisions

2.0.0 is the cleanup major that closes the 1.x roadmap. Its only job is to remove the 1.0
configuration aliases and the support floors that only a major may move. Everything else
(canonical configuration and defaults, the JSON schema's canonical properties, every `exports`
subpath, plugin API v1, every CLI command, the JSON-LD components and `AeoHead`, the frozen
`validate` and `ValidateResult`, the audit registry, the Accept contract, versioned manifests,
the package layout and its five runtime dependencies) is kept.

A second, larger plan proposed on 2026-10-19 (plugin API v2, renamed page-record fields, a
parser-backed `migrate` command with a new dependency, a third-party package analysis registry)
was not adopted: it would have turned the cleanup into a feature release that breaks every
plugin without a new capability, and it would have broken the frozen `golden-1.0` test. Its
useful parts are kept: the closure ledger, machine-readable compatibility evidence, honest
"not shipped" dispositions, and a check of doctor's `astro-llms-txt` advice.

| # | Decision | Why |
| --- | --- | --- |
| D1 | A 1.0 key is a build-stopping `AeoConfigError` that names every removed path and its canonical path, and prints the paste-ready canonical block (the 1.x `printMigration` renderer). A key set to `undefined` is ignored, as before. A removed block with no recognized key inside (`dotmd: {}`) is still rejected, naming the block. | A silent "unknown key (ignored)" warning would drop a 1.0 `robots.txt` policy or frontmatter without anyone noticing. |
| D2 | Floors rise to Astro 6 and Node 22.12.0 (release-owner decision, 2026-10-19): `peerDependencies.astro` is `>=6.0.0` and `engines.node` is `>=22.12.0`, Astro 6 and 7's own Node floor. Astro 5 users stay on 1.6.x. | Node 20 reached end of life on 2026-04-30. No supported Astro user is excluded, and only a major may move a floor. |
| D3 | The plugin API stays `apiVersion: 1`. | A v2 that preserves every stage and its ordering would be a number change that breaks every plugin for nothing. |
| D4 | The flat `AeoPageRecord` mirrors (`url`, `mdHref`, `title`, `description`, `markdown`, `lastModified`, `aeoTokens`) and `source.strategy` are kept and documented as stable, no longer deprecated. | Outside the roadmap's 2.0 scope. Runtime hooks already receive the nested-only projection; removing `aeoTokens` would touch opt-out enforcement (`no-dotmd`, `no-llms`, `no-llms-full`) for no user benefit. |
| D5 | Two declared-1.x-only removals ship with the configuration cleanup: `AeoHeadProps.author` (use `authors`) and the `CatalogPage` alias (use `PageDescriptor`). A leftover runtime `author` prop is reported as the `aeo-head-author-removed` warning rather than dropped silently. | Both declarations said "retained through 1.x". The warning costs one registry entry and keeps a JavaScript project from losing its author tags unnoticed. |
| D6 | No `migrate` command and no parser dependency. The path is: on 1.6.x run `AEO_PRINT_MIGRATION=1 astro build`, paste the block, upgrade; on 2.0 the D1 error prints the same block. `doctor` gains a low-confidence `removed-config:<key>` text hint. | AGENTS.md forbids a new dependency without a strong reason, and a binding-aware analyzer would duplicate what the printer and the error already give. |
| D7 | The roadmap's "migration analyzers for SEO, Markdown and llms.txt integrations" are closed at the level that shipped: `doctor` package-overlap hints. Recorded as reduced scope in the closure ledger. | An honest closure beats a version-pinned registry of third-party packages that nobody maintains. |

## Implementation notes

- `printMigration` and `liftLegacy` stay in `src/lib/config-removed.js` (renamed from
  `config-migrate.js`), so the error prints exactly what the 1.x printer printed, with the 1.0
  precedence (`frontmatter` over `dotmdMetadata`, `email` over `contact`) and the
  `sitemap.enabled: false` to `mode: 'external'` mapping. An empty object now renders as `{}`.
- `resolveConfig` still works on an `undefined`-stripped deep copy of the input, which the 1.x
  merge produced as a side effect, so an explicit `undefined` keeps falling through to defaults.
- `starlightAeo()` and `emdashAeo()` pass a 1.0 key through to `aeo()`, so both report it with
  the shared error instead of their own wording.
- `fixtures/golden-1.0` now builds from its configuration translated key for key into canonical
  spelling. `expected.json` is unchanged and still matches byte for byte on Astro 7, which is the
  strongest proof that the translation table is exact.
- `fixtures/config-compat` became the 1.6-to-2.0 parity gate. Each of its pages now carries an
  explicit modified time, so no output depends on git history. `expected-1.6.json` was generated
  once by building the canonical config with the published 1.6.1 source (a detached `1.6.1`
  worktree under `.context/`, Astro 7.3.5, Node 24.15.0) and must not be regenerated from the
  current implementation.
- The upstream `astro-llms-txt` package (0.0.1-beta, npm README checked 2026-10-22) generates
  only `/llms.txt`, so doctor's `llms.txt` overlap label is correct and unchanged.
- CI keeps installing on Node 24 and switching down for the floor leg, because pnpm 11 needs
  Node 22.13. The floor leg now runs the whole default suite, build e2e included, so the
  `*.e2e.test.js` exclusion is gone.

## Release mechanics

`package.json` was already set to `2.0.0` with a placeholder changelog entry before this work
(`c3fe7f2`). There is no Changeset to consume: running `pnpm changeset version` on a `major`
Changeset would have produced 3.0.0. The `## 2.0.0` changelog section is written by hand, and
`scripts/check-changesets.mjs` accepts it as an already-versioned release.
