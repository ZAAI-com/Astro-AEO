# Astro-AEO 1.5.1 semantic validation evidence

Semantic validation for 1.5.1 carries forward from the 1.5.0 record. 1.5.1 accepts local `http:`
hreflang alternates, adds documented training crawlers to the registry, reports small-corpus
truncation as info, and gives `FaqJsonLd` an optional `id`. The last change touches a
JSON-LD-producing component, so the carry-forward is proven by rebuilding the fixture rather than
asserted from the diff: the rebuilt fixture HTML is byte-identical to the 1.4.0 and 1.5.0
submission, and no resubmission to the external validators was required. The external services are
manual release checks, not automated release dependencies.

## Behavior change recorded for this release

Plain `http:` hreflang alternates on `localhost`, `127.0.0.1` and `[::1]` are accepted when the page
or sitemap entry is served from one of those hosts, or while `astro dev` or `astro preview` runs. A
production build for an https site still rejects them. `robots.txt` presets now address
`Applebot-Extended`, `Meta-ExternalAgent`, `Amazonbot` and `CCBot`. `small-corpus-truncated` moves
from warning to info. `FaqJsonLd` output is unchanged unless `id` is passed. The changelog lists
each change.
