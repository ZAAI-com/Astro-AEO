# 1.6.0 decisions and measurement policy

## Baseline

The performance reference is reconstructed commit `29729bb`, after the inactive
tab and incomplete production corpus fixes, before the shared feature contracts.
It is not a published 1.5.4 release. An isolated detached checkout with its own
offline, frozen-lockfile installation produced
`benchmarks/baseline-postfix-29729bb.json`. Node and Cloudflare adapter fixtures,
matching no-integration fixtures, paired HTTP samples and local workerd startup
profiling were measured. No deployed provider was tested.

The baseline already fails the unpacked package gate: 1,530,283 bytes against
1,530,000. The attachment's 1,470,000-byte ceiling predates the measured 1.5.3
content/schema additions documented in `benchmarks/thresholds.mjs`. The current
gate remains unchanged. Any increase needs measured before/after evidence and
explicit release-owner approval. A failed measurement remains recorded as failed.

Timing comparisons require the reference runner. Local timings are observations,
not proof of the 5% overhead target. Package/output/bundle bytes, memory and warm
cache work remain blocking regardless of runner.

## Architecture decisions

| Area | Decision |
| --- | --- |
| Page model | Retain `AeoPageRecord` and compatibility aliases. Deprecate, do not remove, legacy page fields. |
| Extraction selectors | Retain configured selector order, removal precedence, and rendered fallback. |
| Migration | Keep `LEGACY_MOVES` authoritative, accepted legacy spelling and explicit conflict warnings. |
| Validation | Freeze `validate`, its formatter output and `ValidateResult`; put new checks in audit. |
| Audit categories | Keep eight registry categories; document their mapping to the roadmap's five groups without renaming rule IDs. |
| Semantic conversion | Preserve authored canonical and graph precedence; fill only permitted missing values. No `schema.conflicts` option. |
| Entity IDs | Retain current explicit/inferred ID rules and malformed FAQ-ID safeguards. |
| Artifact ownership | All public output uses existing writer arbitration, including versions and RAG. No parallel writer or ownership-by-package-name heuristic. |
| Sources | Retain held bodies in the internal source record and hash actual bytes. Catalog hash claims are not authoritative. Never publish raw MDX. |
| Privacy | Reports, analytics and private evidence exclude raw content, absolute paths and credentials. Processing-cache payloads are not evidence exports. |
| Compatibility | Preserve Node 20.19.5 and Astro 5 floors. Anonymous live corpora need Astro 6.3+; older Astro fails closed, while direct companions remain supported. |
| Optional dependencies | Add no mandatory runtime dependency. OpenTelemetry remains optional; Node sinks never enter core/runtime import closures. |
| Provider evidence | Local emitted-handler and workerd contracts are not deployed-provider verification. Only doctor URL probes can earn `configured`. |
| Starlight | Use public route data and explicit version configuration; defer automatic upstream version discovery. |
| HTTP cache policy | Omission inherits representation policy; explicit Markdown Cache-Control applies to generated Markdown, not application redirects or HTML. |
| Incremental safety | Cache only declared pure/versioned extension stages; preserve unrelated cache stages, read-only safeguards and incomplete inventories. |

## Release evidence

Record actual command results, failures, manual semantic checks and provider
verification limits as work completes. Do not infer successful checks from a plan
or a prior release. Do not consume Changesets, tag or publish until final release
preparation and the authorized gates are complete.

### Layered processing and private evidence

The batch-4 quick release check passed 2,439 tests in 137 files, source and
TypeScript 5.5 consumer checks, schema freshness, migration freshness, Changeset
coverage and release metadata. Tarball inspection still failed: 1,596,242 unpacked
bytes against the unchanged 1,530,000-byte gate. Batch 3 measured 1,569,051 bytes;
this batch adds 27,191 bytes. This records the deviation, not approval to raise
the limit.

The real collection regression uses 10,000 rendered page files: a warm run makes
zero extractor or declared-renderer calls, and one page edit makes exactly one
of each. This is a work-count regression, not the final paired reference-runner
timing or memory benchmark. Additional tests cover dependency retention across
cache sweeps, unrelated-stage preservation, scoped locale invalidation, snapshot
redaction/digests/permissions, identical mtimes, output restoration, incomplete
inventories, locks, rollback and symlink refusal. Runtime semantic declarations
are matched to the internal loader manifest; the frozen validation contracts
and import-boundary checks pass in the default suite.

### Heading-aware corpus and locale completion

The batch-5 quick release check passed 2,453 tests in 139 files, both type
checks, schema and migration freshness, Changeset coverage and release metadata.
Tarball inspection remains blocking: 1,607,850 unpacked bytes against the
unchanged 1,530,000-byte gate, an 11,608-byte increase over batch 4. This
measurement does not authorize a higher limit. The check ran locally on Node
24.15.0, not the final supported-version or reference-runner matrix.

Manual semantic review checked that a heading travels with its first content
block, a fitting section moves to a fresh chunk only when needed, and lookahead
does not double-count page wrappers. Tests preserve whole oversized fences and
units, compare static and runtime logical bytes and manifests, disclose only
sanitized tokenizer fallback reasons, and verify per-origin profile inheritance.
Explicit unresolved-language policies now apply without an Astro locale table;
known alternate clusters and sitemap entries detect disagreeing x-default targets.
Multi-origin IndexNow tests keep host-specific key references separate and
withhold removals for incomplete inventories. Existing alias/gzip and default
robots golden contracts pass.

Observable crawler registry version 2 is separate from the unchanged robots
registry. Apple and Amazon additions were checked against first-party docs on
2026-10-03; User-Agent tokens remain claims, not verified operator identity.
Meta's first-party page was unavailable, so its older verification date is
preserved and no additional Meta identities are inferred. Final external
provider verification and release-wide measurements remain outstanding.

### Versioned corpus topology

The batch-6 quick release check passed 2,483 tests in 144 files, both type
checks, schema and migration freshness, Changeset coverage and release metadata.
The dedicated development fallback-route file passed all 9 tests. These are
local Astro 7 / Node 24 checks, not the final supported-version matrix.
Tarball inspection remains blocking: 1,640,237 unpacked bytes against the
unchanged 1,530,000-byte ceiling. This is 32,387 bytes above batch 5 and
110,237 bytes above the ceiling; no threshold increase is authorized. The
added bytes provide the node-free shared topology, reciprocal version identity,
partitioned plans, transport/declarations and their consumer documentation.

Manual semantic review verified that current paths stay unchanged, archives
insert below the existing locale prefix, and the Astro base affects URLs rather
than physical output directories. The actual static build uses two locales and
two versions under `/docs`; its reciprocal records, scoped manifests, aliases,
gzip and original companion paths agree. Actual development requests exercise
archive corpora, scoped manifests and manifest-referenced chunks through a
redirect-owned 404. A direct regression compares static and runtime scoped
manifest bytes with compression disabled; runtime manifests intentionally omit
static gzip records. Default disabled-feature goldens and node-free boundaries
pass in the broad suite.

Version identity removes only configured base/locale and matching version
prefixes, each at most once; authored `versionGroup` handles renamed routes.
Alternates remain locale-scoped and reciprocal. Authored canonical/graph
precedence and language alternatives remain intact. Versioned live-corpus hooks
run once per page after private marker collection so they see complete peers;
the internal derived-link tracking field never reaches those public hooks.
Ambiguous/conflicting identities fail closed. Audit checks use known records
only and do not claim external target verification. Public RAG path planning is
shared here, but RAG generation remains batch 9. Explicit Starlight version
interpretation and fallback exclusion remain batch 7. No deployed-provider,
final timing/memory or release-wide compatibility claims are made by this batch.
