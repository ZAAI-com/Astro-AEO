# 1.6.0 decisions and measurement policy

## Baseline

The performance reference is reconstructed commit `29729bb`, after the inactive
tab and incomplete production corpus fixes, before the shared feature contracts.
It is not a published 1.5.4 release. An isolated detached checkout with its own
offline, frozen-lockfile installation produced
`benchmarks/baseline-postfix-29729bb.json`. Node and Cloudflare adapter fixtures,
matching no-integration fixtures, paired HTTP samples and local workerd startup
profiling were measured. No deployed provider was tested.

The baseline already fails the unpacked package gate: 1,530,283 bytes against
1,530,000. The attachment's 1,470,000-byte ceiling predates the measured 1.5.3
content/schema additions documented in `benchmarks/thresholds.mjs`. The current
gate remains unchanged. Any increase needs measured before/after evidence and
explicit release-owner approval. A failed measurement remains recorded as failed.

Timing comparisons require the reference runner. Local timings are observations,
not proof of the 5% overhead target. Package/output/bundle bytes, memory and warm
cache work remain blocking regardless of runner.

## Architecture decisions

| Area | Decision |
| --- | --- |
| Page model | Retain `AeoPageRecord` and compatibility aliases. Deprecate, do not remove, legacy page fields. |
| Extraction selectors | Retain configured selector order, removal precedence, and rendered fallback. |
| Migration | Keep `LEGACY_MOVES` authoritative, accepted legacy spelling and explicit conflict warnings. |
| Validation | Freeze `validate`, its formatter output and `ValidateResult`; put new checks in audit. |
| Audit categories | Keep eight registry categories; document their mapping to the roadmap's five groups without renaming rule IDs. |
| Semantic conversion | Preserve authored canonical and graph precedence; fill only permitted missing values. No `schema.conflicts` option. |
| Entity IDs | Retain current explicit/inferred ID rules and malformed FAQ-ID safeguards. |
| Artifact ownership | All public output uses existing writer arbitration, including versions and RAG. No parallel writer or ownership-by-package-name heuristic. |
| Sources | Retain held bodies in the internal source record and hash actual bytes. Catalog hash claims are not authoritative. Never publish raw MDX. |
| Privacy | Reports, analytics and private evidence exclude raw content, absolute paths and credentials. Processing-cache payloads are not evidence exports. |
| Compatibility | Preserve Node 20.19.5 and Astro 5 floors. Anonymous live corpora need Astro 6.3+; older Astro fails closed, while direct companions remain supported. |
| Optional dependencies | Add no mandatory runtime dependency. OpenTelemetry remains optional; Node sinks never enter core/runtime import closures. |
| Provider evidence | Local emitted-handler and workerd contracts are not deployed-provider verification. Only doctor URL probes can earn `configured`. |
| Starlight | Use public route data and explicit version configuration; defer automatic upstream version discovery. |
| HTTP cache policy | Omission inherits representation policy; explicit Markdown Cache-Control applies to generated Markdown, not application redirects or HTML. |
| Incremental safety | Cache only declared pure/versioned extension stages; preserve unrelated cache stages, read-only safeguards and incomplete inventories. |

## Release evidence

Record actual command results, failures, manual semantic checks and provider
verification limits as work completes. Do not infer successful checks from a plan
or a prior release. Do not consume Changesets, tag or publish until final release
preparation and the authorized gates are complete.

## Batch 8: opt-in request analytics

The enabled-only Vite resolver retains the bare `astro-aeo/middleware` pre-entry
and wraps the original middleware through a separate generated server module.
The ordinary runtime projection has no analytics configuration or imports.
One real Node fixture proves omitted and explicitly disabled configurations have
byte-identical server bundles, with a fixed fixture-only Astro encryption key,
and an enabled positive control. Enabled output adds no AEO client JavaScript.

Observation returns the original response and never reads its body. Privacy
traps permit only request method, public pathname and User-Agent. Tests cover
minute-rounded UTC, deterministic sampling, registry-v2 claimed identities,
known inventory/companion paths, configured artifact families, bounded route
patterns and `(unlisted)`. IP, query, referrer, cookies, authorization, raw
headers and source/marker payloads never enter events. Cache outcome is only
HTTP 304 `not-modified` or `unknown`, not an inferred host cache hit.

Internal collection, disposable corpus fan-out and development loopback are
excluded through the original middleware state. Real development and Node SSR
requests each record one public event for companions and live corpus responses,
not one event per fan-out render. The fixture deliberately uses a prerendered
endpoint rather than a prerendered page in its live inventory: that tests build
exclusion without relaxing existing fail-closed collection limitations. The
explicit catalog is complete for its on-demand page routes.

Delivery supports mandatory development console, private serialized Node JSONL
(mode `0600`, confined paths and symlink refusal), runtime-secret HTTPS webhooks
(one-event envelopes, manual redirects and two-second timeout), optional-peer
OpenTelemetry counters or OTLP/HTTP JSON (no path attributes), and validated
JSON-configured modules. No mandatory runtime dependency was added. Cloudflare
workerd and Deno are not supported JSONL surfaces. Module preflight is strict
when configured; runtime import/setup errors are caught, and even a hanging
runtime factory does not delay visitor HTTP responses. Delivery failures report
sanitized messages once per observer. Request-lifetime callbacks receive caught
work; otherwise delivery remains caught, best-effort fire-and-forget.

Provider observers are explicitly injected. Static edge integration configuration
never installs deployment handlers. Cloudflare Pages/Workers, Netlify and Vercel
injection contracts are tested locally; Vercel records routing responses, not
final origin status. The [Cloudflare lifetime API](https://developers.cloudflare.com/workers/runtime-apis/context/),
[Netlify Edge API](https://docs.netlify.com/build/edge-functions/api/),
[Vercel functions API](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#waituntil),
and [Astro Cloudflare runtime API](https://docs.astro.build/en/guides/integrations-guide/cloudflare/)
were checked on 2026-10-03, alongside installed adapter source. No deployed
canary, host-log ingestion, external webhook delivery or upstream dashboard was run.

Final local checks: 2,563 default tests in 152 files, source typecheck, TypeScript
5.5 consumer checks, schema freshness, migration-doc freshness, Changeset coverage
and release metadata pass. Separate real analytics checks pass: three Node SSR
tests, one development test, and 29 workerd edge contract tests. The audit registry
collector excludes the analytics cache outcome literal `not-modified` from its
non-diagnostic ternary matches; no audit rule or category was added.

Quick release stops only at package size. Its checked unpacked size is 1,696,432
bytes; a subsequent README indentation-only change gives the final inspected
1,696,442 bytes: 40,532 above batch 7 and 166,442 above the unchanged 1,530,000-byte

## Batch 9: private RAG records (2026-10-03)

- Opt-in RAG uses the existing heading-aware Markdown units and complete-text tokenizer
  transaction. Full-page records and chunk records expose stable IDs, exact text hashes,
  measured token counts, approximation/fallback identity, headings and flat metadata. Chunk
  continuation metadata retains ancestor headings without repeating text. Oversized indivisible
  units remain whole and emit the corpus-category `rag-chunk-over-budget` diagnostic.
- Record identity hashes public canonical URL, route pathname, locale and version, with ordinal chunk suffixes.
  Content edits change hashes; insertions that shift chunk ordinals can change later IDs. The
  logical version topology, not a separate RAG route planner, controls root/locale/archive paths.
  RAG ignores `full.mode` truncation but honors indexing, corpus/section and locale-fallback
  exclusions. Raw source/MDX and rendered HTML never enter default records.
- `rag:record` runs through the existing build/runtime dispatchers after tokenizer fallback, so
  partial raw plans never run hooks. If replacement metadata makes custom JSONL counting fail,
  every family/version restarts with the fallback counter and hooks are revalidated. Replacement enriches flat metadata only; protected
  identity, URL/path/locale/version, text, headings and measurements stay immutable. Text changes
  belong in `page:transform`. An explicit drop removes one record. Malformed replacement,
  nonrecoverable exception, runtime module failure or explicit isolation withholds the export.
  Authorized thrown exceptions alone keep the last valid record and continue later hooks.
- Private locale/version JSONL and its versioned index are `0600` writes in the existing
  transaction. These are intentional content exports, not sanitized evidence. Snapshots include
  only their canonical-order hash, and snapshot, trace and RAG index share the content-derived
  build digest. Runtime-owned or incomplete build exports declare `buildTimeIncomplete: true`.
  The real Node fixture correctly reports `inventoryComplete: false` for unavailable build-time
  HTML, without relaxing the existing completeness safeguard.
- Publishing requires explicit `publish: true`. Public JSONL uses the normal ownership writer,
  artifact etags, manifest filtering, deterministic static gzip, symlink checks and safe stale
  deletion. RAG may be the only enabled public corpus family. Validator compatibility accepts
  the new artifact kind using existing hash/token/gzip checks, with no new validator finding or
  output formatting contract. The frozen legacy validator suite passes unchanged.
- The RAG planning cache keys published content, page metadata, budget, section results,
  tokenizer/options/module and package producer identity. Hook caches remain separate and
  undeclared/unsafe hooks bypass only their own stage. Warm record/count stages reuse cached
  work. Private restoration preserves identical mtimes and refuses symlinks before public writes.
- Source and TypeScript 5.5 consumer checks, schema/migration-doc freshness, Changeset coverage
  and release metadata pass. The quick gate passes 2,591 tests across 155 files. The separate
  real Node SSR RAG test passes, including public base/locale/archive requests, runtime metadata
  replacement, HEAD, private digest/incompleteness disclosure and fail-closed malformed hooks.
- Manual semantic review covered the shared planner's text/hash/count agreement, archive versus
  current text selection, heading continuation metadata, read-only private index linkage, public
  ownership/gzip handling, and the absence of raw source in record projections. The real static
  fixture preserves companions, reciprocal version alternates and its no-client-JavaScript check.
- Packed-tarball inspection measures **455,184 packed bytes** and **1,728,648 unpacked bytes**.
  The unpacked increase from batch 8's final inspection is **32,206 bytes**, attributable to RAG
  implementation, public schemas/declarations and README documentation. Quick release checking
  stops at package size: packed exceeds **450,000** by **5,184**, unpacked exceeds the unchanged
  **1,530,000** ceiling by **198,648**. Neither ceiling was increased, and this evidence is not
  approval for an increase. Inspection-only size bypass is not a passing release gate.
- LangChain and LlamaIndex mappings are documentation examples using the consumer's own
  dependencies, checked against primary document references on 2026-10-03. No framework or
  mandatory runtime dependency was added. The reusable planner works without public publishing;
  file/manifest companion fallback export and the `report rag` command remain batch 10 work.
- Provider claims remain local and unverified in deployment. No tag or publication was made.
  The unrelated release-workflow edit remains outside this batch.


## Batch 10: read-only reports and inspection

- Add traffic, changes, inspect, graph and RAG command dispatch without evaluating consumer
  configuration or modules. The relocated validator formatter preserves exact human/JSON
  output, including strict and quiet behavior; the original internal import remains compatible.
- Bound UTF-8 files, stdin and URL streams to 16 MiB, event rows to 100,000 and lines to
  64 KiB. Companion and graph traversal have documented depth/work caps. Reject malformed
  contracts, unexpected privacy fields, credentials, unsafe paths and linked project inputs.
  Explicit report exports use an atomic 0600 transaction, never overwrite consumed inputs,
  build companions or private build evidence, and create nothing during ordinary inspection.
- Traffic reports observed counts, UTC inclusive-from/exclusive-to filters, coverage, claimed
  identity, sample rates, surfaces and scopes. Optional inverse-probability estimates disclose
  their assumptions and cannot estimate coverage gaps. URL changes baselines reject redirects,
  use a two-second timeout, bound response bytes and return sanitized errors.
- Changes compare page components and ownership etags. Incomplete or digest-mismatched current
  inventories leave removals unconfirmed; incomplete baselines leave additions unconfirmed.
  The default failure gate is none. Inspection joins private snapshots/traces and manifests,

- Graph reports resolve no remote contexts or references. Offline HTML contains a complete

- Source and TypeScript 5.5 consumer checks, schema and migration freshness, Changeset coverage,

### Audit evidence and Action reporting (batch 11)

- Readiness-v2 retains the eight categories, 15/5/0 weights and 30-point rule cap,
  but scores only observed, applicable categories. Unknown/not-applicable coverage
  is explicit; no applicable category yields a null overall score. Editorial advice
  remains score-neutral. Existing readiness-v1 reports remain schema-compatible.
- Audit regions describe rendered HTML or published companion Markdown, with
  one-based UTF-16 columns and exclusive ends. Comments, raw-text elements,
  ambiguous tags and fenced examples cannot create guessed author-source locations.
  SARIF keeps file regions separate from URL evidence. URL Action annotations and
  Markdown summaries come from the same observation as SARIF, without a second crawl.

  entities. Unvisited live documents remain unknown. Visible main-content duplicates
  require substantial indexable content within a locale/version; shared chrome and
  canonical aliases do not create content findings. Findings contain no source bodies.
- Local private evidence reads are bounded and symlink-safe. Output, snapshot, trace,
  ownership and deployment identities are cross-checked; mismatches prevent complete
  inventory claims and receive a sanitized audit finding.
- Live discovery is explicit (`--discovery`, optional deployment base), bounded to
  100 resources and 16 MiB of inspected text, and uses anonymous origin/redirect/body
  safeguards. Validate discovery text, optional profile/manifest, sitemap XML and
  identity artifact/companion hashes and built-in counts. Disclose custom counts,
  compressed wire bytes, runtime-owned omissions and capped discovery. No deployed
  provider certification or consumer-module execution is implied.
