## Release boundaries and handoff

Changesets were consumed from the released `origin/main` 1.5.3 version basis into exactly 1.6.0,
preserving curated implementation notes. Temporarily restoring that released numeric basis
prevented the already assembled 1.6.0 working package from incorrectly becoming 1.7.0.
This is release preparation only, with no tag or publish.

[Semantic evidence](1.6.0-semantic-validation.md) records exact HTML byte equivalence with prior
accepted 1.5.3 submissions, expected hostile fixture findings, and absent collection/client
markers. New external validator submission and final release-owner acceptance are not claimed.

The unrelated W2 npm/OIDC edit remains untouched and excluded. The separately reviewable
`.context/batch12-release-gates.patch` adds only shared exact Deno setup and full baseline history;
it must be applied before a separately authorized tag gate. W1 already has both requirements.
Renovate app activation, hosted compatibility jobs, the declared timing reference runner and
deployed provider certification remain external. Vercel/Netlify evidence remains local.

After an approved batch-12 commit and push, rerun Git installation at its actual new revision.
The package decision is resolved. Before tagging, apply the isolated W2 gate patch, record final
semantic acceptance, and run strict clean/tag gates. Tagging and publication are not authorized.
